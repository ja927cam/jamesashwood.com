Maps that work without a connection

OsmAnd, OpenStreetMap data and keeping the useful parts of a map stack local.

9 November 2026 4 min read Maps · Data

A map looks like one thing on a phone. Underneath it is at least four: a set of tiles to draw, a search index, a routing graph and a pile of metadata. “Offline maps” usually means downloading all four for a region, and the interesting engineering is in which of them you actually need.

I've been using OsmAnd for offline regions and playing with OpenStreetMap data on a home server. The contrast is useful: OsmAnd gives you a polished offline client with routing and search, while a local stack lets you keep private layers and edit the data you care about.

Tiles are for looking, data is for asking

Raster tiles are just pictures in a pyramid. They are simple to serve and cache, but they cannot be restyled and they get expensive at high zoom. Vector tiles keep the geometry and let the client decide how to draw it; the trade is a renderer and a style to maintain.

For a personal map server, the split matters more than the format. Viewing wants tiles at a few zoom levels. Asking questions wants the actual geometry in a database, with coordinates in a known CRS and an index that can answer “what is near here?” without scanning a million features.

OsmAnd does the hard offline part

The reason OsmAnd is useful offline is not only that it stores tiles. It also ships a routing graph and search data for the region, which is the part people forget when they imagine a map download as a folder of images. A route that works in a tunnel is a different engineering problem from a map that renders in a tunnel.

That is also why region sizes vary so much. A city with dense footpaths can cost more than a much larger area of empty land, because the graph and the address data are doing the work.

Keeping private layers at home

On the server side I've been using Strata, a small geospatial workspace built around PostGIS, MapLibre and TileServer GL. The useful part is not serving another basemap; it is being able to import a GeoJSON file, a GPX track or a batch of geotagged photos, keep them private, and still see them on the same map as OpenStreetMap data.

That introduces the usual geographic annoyances: CRS detection and reprojection, invalid geometry, clipping, and deciding whether a feature is a tile or a row. The answer is usually “both”: a fast, denormalised representation for drawing and a normalised one for editing and history.

The bit I keep coming back to

Offline maps are a good reminder that “the cloud” is mostly a cache with better marketing. If the data is small enough and the formats are open, a phone and a home server can do a surprising amount without a network. The hard part is not storage; it is keeping the four maps — tiles, search, routing and data — consistent with each other.
